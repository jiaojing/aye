# Scope Align

将用户目标对应到一次可 review 的交付。PR 修改范围是本次工作的边界，bounded context 是长期的业务语义与规则边界，两者不等同。

## 何时需要对齐

- 请求存在会改变交付结果的歧义；
- 初次进入领域，尚不清楚规则归属或相关 consumer；
- 预计改变领域职责、公开契约、持久化语义，或扩大原请求。

目标和影响明确时，简述范围后直接实施；多文件、跨 crate 或新增辅助文件本身不要求用户再次确认。

## 对齐内容

按需要说明：

- **In**：交付行为和主要修改位置；
- **Out**：真实可能漂移、但此次不做的方向；
- **领域与契约**：规则归属哪个领域，使用还是改变邻接契约；
- **不确定项**：只列影响目标、风险或授权的真实未知项。

文件清单用于理解影响，不是阅读白名单或不可调整的实现承诺。根据实际依赖补读契约、调用方和测试。

## 实施中

- 复用用户已给出的目标、决策和授权。明确请求所需的常规可逆修改可以自主完成。
- 用户明确要求先确认方案时停在提议；其他情况下只对尚未覆盖的关键决策提问。
- 必要的辅助文件、测试和接线可以纳入原目标并报告；真实扩张交付或发现重大未决风险时重新对齐受影响部分。
- 用户已有修改与本次工作区分清楚，不覆盖无关内容。

验收、设计和实施的分流见 `flow`；已有明确验收和方案时直接复用。
