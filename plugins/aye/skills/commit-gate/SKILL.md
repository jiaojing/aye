# Commit Gate

提交前确认变更可 review、验证充分且操作已获授权。工作完成不要求自动 commit/push；遵循用户实际请求。

## 准备与授权

- 检查 diff、相关验收和验证结果，说明行为变化、主要位置与实际风险。
- 重要领域边界、公开契约或持久化变化缺少审查时，按 `review` 补检查；不按行数触发。
- commit 与 push 分别需要请求或适用的既有授权。一次“commit + push”可以覆盖两项；同一任务的授权持续有效，不在每步重新询问。
- 授权范围未覆盖某项操作时，在结果已可 review 后询问；不从提交授权推断推送、发布或其他无关动作。
- 新增重要交付内容或出现未被覆盖的重大风险时，重新对齐受影响的操作。

## 检查

- 已完成与此次风险相称的验证，缺失部分明确报告。
- diff 符合交付目标，没有混入无关改动、调试残留、生成物或秘密。
- 用户已有修改未被覆盖或未经说明混入提交。
- 公开契约、旧数据或工具链变化有相应兼容与迁移证据。

摘要长度按变化与风险决定；关键 diff 有解释，不只展示 stat。拆分 commit 时按可 review 的交付与回滚关系决定。

## Commit Message

遵循仓库约定；本项目默认中文、标题简短具体，正文说明必要的原因和风险。配套文档或配置同步不单独充当主题，不添加 AI 标注或 `Co-Authored-By`。

## 完成后

- 报告执行的操作、提交及推送范围；未执行或失败的操作如实区分。
- 若存在本轮 feature/task 文档，回写完成的任务、验收和对应 sha；未推送不标成已推送，不为打勾创建新 feature。
- 不自动生成 handoff 或宣布 session 结束；接力与其他流程关系见 `flow`。
