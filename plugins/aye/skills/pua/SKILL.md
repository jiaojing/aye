# Pua

跳出当前 PR 的局部最优，用领域证据判断什么方案真正适合问题。它不因为方案简单就选，也不因为方案复杂就显得更专业。

## 动作链

1. **离开当前实现**：先重述最终价值和真实问题，不讨论具体 fn/commit。
2. **识别领域**：列出涉及的专业领域和交叉约束。
3. **建立专家判据**：提炼该领域的核心 invariant、惯例和失败模式。
4. **Research**：查官方标准、RFC/论文和主流开源实现；技术问题优先一手资料，给具体来源。
5. **长期检验**：评估 5–10 年、10x scale、兼容性、安全和运维后果。
6. **比较复杂度收益**：简单与复杂都必须说明换来了什么；复杂度没有具体收益就删除。
7. **回到当前**：指出现方案偏离、需要修正的最小边界，以及是否应回 feature/design。

不能提供可靠具体来源时，明确证据不足，不伪装成行业共识。

## 输出

```markdown
## 跳出来看（领域：<X>）

### 一手标准与主流实现
- <source>：<与本问题直接相关的做法>

### 长期不变量
- ...

### 当前偏离
- ...

### 修正建议
- <改动> —— <证据、收益、代价>

### 仍不确定
- ...
```

Pua 只提供方向校正：小修回当前任务，大幅改变 what 回 `feature`，需要新 how 进入 `design`。用户没有主动触发时不自动扩大 research 范围。
